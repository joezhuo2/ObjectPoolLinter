# OPL006: Managed field in job struct

| | |
|---|---|
| **Rule ID** | OPL006 |
| **Category** | Usage |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | No |
| **Since** | 1.5.6 |

## Cause

A struct that implements a Unity job interface has an instance field (or auto-property) of a managed
type:

- a reference type: a class, interface, delegate, array or `string`, or a type parameter constrained to
  `class`;
- a struct that holds one of those, at any depth.

`Schedule()` copies the job struct into native memory, where the garbage collector cannot track a
reference, so the job system checks the struct first and throws:

```
InvalidOperationException: MoveJob.Label is not a value type. Job structs may not contain any reference types.
```

The C# compiler accepts the struct, so without this rule the mistake shows up only when the code runs.

The message names the field, the job struct and what makes the field managed:

```
Field 'Label' of job struct 'MoveJob' has the reference type 'string'. Unity throws InvalidOperationException when the job is scheduled.
Field 'Item' of job struct 'LoadJob' has the type 'Payload', which holds 'Data.Name' of reference type 'string'. Unity throws InvalidOperationException when the job is scheduled.
```

### Which structs are job structs

A struct is checked when it implements, directly or through another interface, one of:

- `Unity.Jobs.IJob`, `IJobFor`, `IJobParallelFor`;
- `UnityEngine.Jobs.IJobParallelForTransform`;
- from the Collections package: `IJobParallelForBatch`, `IJobParallelForDefer`, `IJobFilter`,
  `IJobParallelForFilter`;
- from Entities: `IJobChunk`, `IJobEntity`;
- any other interface marked `[JobProducerType]`, which is how Unity declares a job type, so custom
  job interfaces are covered too.

The rule runs only when the compilation references at least one of these. Unlike OPL001 to OPL003, it
does not depend on hot paths or `MonoBehaviour`: a job struct is checked wherever it is declared.

## Example

```csharp
using Unity.Collections;
using Unity.Jobs;
using Unity.Mathematics;
using UnityEngine;

public struct Payload
{
    public int Id;
    public string Name;
}

public struct MoveJob : IJob
{
    public NativeArray<float3> Positions;   // fine: a native container
    public float DeltaTime;                  // fine: a value type
    public string Label;                     // OPL006: has the reference type 'string'
    public Transform Target;                 // OPL006: has the reference type 'Transform'
    public Payload Item;                     // OPL006: has the type 'Payload', which holds 'Name' ...

    public void Execute() { }
}
```

## What is not reported, and why

- **Native containers.** `NativeArray<T>`, `NativeList<T>`, `NativeHashMap<TKey, TValue>` and any
  other struct marked `[NativeContainer]` hold a managed `DisposeSentinel` while safety checks are on;
  the job system knows about it and clears it on schedule.
- **Fields marked `[NativeSetClassTypeToNullOnSchedule]`**, which the job system sets to `null` before
  the job runs.
- **Static fields and constants.** They are not part of the copied struct. (Reading a managed static
  from a Burst-compiled job is still an error, but Burst reports that itself.)
- **Properties with a body** (`string Name => ...`). They store nothing.
- **Unconstrained type parameters.** `public T Value;` is safe or not depending on the type argument,
  which the job system checks when the job is scheduled.
- **Pointers, enums and fixed-size buffers.** They are value types.
- **Job classes.** A class implementing `IJob` cannot be scheduled at all; the compiler's constraint
  on `Schedule<T>() where T : struct, IJob` rejects it already.
- **Private fields of structs from compiled assemblies**, when the reference does not expose them.
  Structs declared in source are always inspected in full.

## How to fix

| Field type | Replace with |
| --- | --- |
| `T[]`, `List<T>` | `NativeArray<T>`, `NativeList<T>` (allocate before scheduling, dispose after completing) |
| `Dictionary<TKey, TValue>` | `NativeHashMap<TKey, TValue>` |
| `string` | `FixedString32Bytes` / `FixedString64Bytes` (Collections package), or an index into data kept outside the job |
| `Transform` | `IJobParallelForTransform` with a `TransformAccessArray`, or copy the positions into a `NativeArray<float3>` first |
| A `MonoBehaviour`, `ScriptableObject` or other class | Copy the values the job needs into value-type fields before scheduling, and write results back after `Complete()` |
| A delegate | `FunctionPointer<T>` from Burst, or a value-type switch on a mode enum |

## When to suppress

A job struct that is never scheduled, only called as `job.Execute()` on the main thread, can hold
managed fields; suppress there, and consider whether it needs to be a job at all.

```csharp
#pragma warning disable OPL006 // Managed field in job struct
    public string Label;
#pragma warning restore OPL006
```

```ini
[*.cs]
dotnet_diagnostic.OPL006.severity = none
```
