# OPL010: ObjectPoolLinter telemetry summary

| | |
|---|---|
| **Rule ID** | OPL010 |
| **Category** | Telemetry |
| **Default severity** | Info |
| **Enabled by default** | Yes, but reported only with `object_pool_linter.telemetry = true` |
| **Code fix** | No |

## Cause

`object_pool_linter.telemetry = true` is set, and the project was compiled. OPL010 is not a problem in
the code: it is the summary [opt-in telemetry](../telemetry.md) produces, reported once per project
build with how many times each ObjectPoolLinter rule fired, most frequent first.

Without the option, OPL010 is never reported and the counting costs one failed table lookup per
diagnostic.

## Example

```ini
[*.cs]
object_pool_linter.telemetry = true
```

```
info OPL010: ObjectPoolLinter telemetry: OPL002: 375, OPL001: 125, OPL003: 125, OPL009: 125 (501 source files)
info OPL010: ObjectPoolLinter telemetry: no diagnostics (42 source files)
```

The diagnostic also carries the counts as properties, one per rule ID plus `SourceFiles`, so a tool
reading a SARIF log (`-p:ErrorLog=build.sarif`) gets them without parsing the message.

## What is counted

- Every diagnostic OPL001, OPL002, OPL003 and OPL006 to OPL009 report, as reported: before
  `#pragma warning disable`, `[SuppressMessage]` and the [automatic suppressions](../suppressions.md)
  remove any. The summary is how often each rule fires on your code, not how many warnings are left.
- Not OPL004 (it is about the config file, not the code), not OPL005 (the source generator reports it,
  outside the analyzer run), and not OPL010 itself.
- A rule switched off with `dotnet_diagnostic.OPL00N.severity = none` does not run, so it counts zero.
- The source file count is every C# file in the compilation, generated ones included.

## Seeing it

Info diagnostics are not printed by `dotnet build` or shown in the Unity Console. Any of these shows
the summary:

- Raise it: `dotnet_diagnostic.OPL010.severity = warning` in the same `.editorconfig`. With
  `TreatWarningsAsErrors` on, that also fails the build, so prefer one of the others there.
- Write a SARIF log: `dotnet build -p:ErrorLog=build.sarif`, then look for `OPL010`.
- In Visual Studio, open the Error List's **Messages** with full-solution analysis on. OPL010 is a
  compilation-end diagnostic, which the IDE computes only for full-solution analysis, and the counts
  there can differ from a command-line build's.

## How to turn it off

Remove `object_pool_linter.telemetry = true`, or set it to `false`. Setting OPL010's severity to
`none` hides the summary but leaves applied code fixes counted in the local file; see
[Telemetry](../telemetry.md).
