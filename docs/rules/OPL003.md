# OPL003: Allocating Unity API in hot path

| | |
|---|---|
| **Rule ID** | OPL003 |
| **Category** | Performance |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes, for `tag` comparisons, `GetComponents*<T>()` and `Input.touches` ([Code fixes](#code-fixes)) |

## Cause

A hot path reads a Unity engine API that returns newly allocated memory on every call. The rule reports:

- **any method or property getter declared in the `UnityEngine`, `UnityEngine.SceneManagement` or
  `UnityEngine.AI` namespace that returns an array.** Unity marshals these out of native memory into a
  fresh managed array each time: `GetComponents<T>()`, `GetComponentsInChildren<T>()`,
  `GetComponentsInParent<T>()`, `Physics.RaycastAll`, `Physics.OverlapSphere`,
  `Physics2D.OverlapCircleAll`, `Object.FindObjectsOfType<T>()`, `GameObject.FindGameObjectsWithTag`,
  `Camera.allCameras`, `Input.touches`, `Mesh.vertices`, `Renderer.materials`,
  `Renderer.sharedMaterials`, `Animator.parameters`, `Scene.GetRootGameObjects()` (since 1.6.1),
  `NavMeshPath.corners` (since 1.6.1), and the rest of that shape;
- **`Object.name`, `Component.tag` and `GameObject.tag`**, which build a new string on every read.
  `gameObject.tag` and `target.tag` on a `GameObject` field are reported as `GameObject.tag`, and `tag`
  on the MonoBehaviour itself as `Component.tag`. `name` is declared once, on `UnityEngine.Object`, so
  it is reported as `Object.name` whatever reference it is read through: a `Component`, `Transform`,
  `Collider` or `GameObject`, `this`, `base`, or a type parameter constrained to `Component`.
  Likewise `transform.tag` is `Component.tag`. A property of your own that hides `name` (`new string
  name`) is not an engine member and is not reported;
- **since 1.6.1, a short list of other members that build a new string or object on every call:**
  `Application.dataPath`, `persistentDataPath`, `streamingAssetsPath` and `temporaryCachePath`;
  `Scene.name` and `Scene.path`; `Animator.GetLayerName(int)`; `Animator.GetParameter(int)`, which
  reads `parameters` (a new array) to return one element of it; `NavMeshAgent.path`, which copies the
  agent's path into a new `NavMeshPath`; and `JsonUtility.ToJson` and `JsonUtility.FromJson<T>`.

The message names the member by its declaring type and the type it returns:
`'Physics.RaycastAll' returns a new 'RaycastHit[]' on every call inside the frequently-called method 'Update'. Use a non-allocating overload or cache the result.`

Which methods count as hot paths follows [OPL001](OPL001.md#cause): the 18 built-in Unity messages on
a `MonoBehaviour`, plus whatever `.editorconfig` adds or excludes (see
[Configuration](OPL001.md#configuration)).

## What is not reported, and why

- **Reads outside a hot path.** `Camera.allCameras`, `Input.touches`, `mesh.vertices` or `tag` in
  `Awake`, `Start`, `OnEnable`, `OnDisable`, `OnDestroy`, `OnTriggerEnter`, a helper method that is not a
  Unity message, or an `Update(int)` overload Unity never calls, run once or rarely and are not reported.
- **`gameObject`, `transform`, `transform.parent` and `Camera.main`.** They return an existing single
  object, not a new array or string.
- **Overloads that fill a buffer you pass in.** `GetComponentsInChildren(List<T>)`,
  `GetComponents(List<T>)`, `GetComponentsInParent(bool, List<T>)`,
  `Renderer.GetSharedMaterials(List<Material>)`, `Scene.GetRootGameObjects(List<GameObject>)`,
  `NavMeshPath.GetCornersNonAlloc`, `Physics.RaycastNonAlloc` and `Physics.OverlapSphereNonAlloc`
  return `void` or a count, not an array. Each call is judged by the overload it binds to, so a method
  that calls both overloads of one API, say `GetComponentsInChildren<Collider>()` and
  `GetComponentsInChildren(_colliders)`, gets one diagnostic, on the array-returning call.
- **Property writes.** `mesh.vertices = buffer` copies into native memory and allocates nothing managed.
- **Members outside `UnityEngine`, `UnityEngine.SceneManagement` and `UnityEngine.AI`.** Packages such
  as `UnityEngine.UI` are managed C# that return their own fields without copying, so they are not
  matched. A look-alike `Game.UnityEngine.Physics` is not matched either. The namespace check is
  exact: the member's namespace must be `UnityEngine` at the root, or `SceneManagement` or `AI`
  directly under it. Every other sub-namespace is left out, even for members that return an array:
  `UnityEngine.Rendering`, `UnityEngine.Animations`, `UnityEngine.Tilemaps`, anything one level below
  the two matched ones (`UnityEngine.AI.Baking`), and an `AI` namespace under another sub-namespace
  (`UnityEngine.Rendering.AI`). The rule does not guess which of those copy; check them in the Unity
  Profiler.
- **Members that return a count or a struct.** `Animator.layerCount`, `Animator.parameterCount`,
  `Input.touchCount`, `Scene.buildIndex` and `SceneManager.GetActiveScene()` allocate nothing.
- **Other string and object members.** Beyond the list above, only `name` and `tag` are common enough
  in per-frame code to be worth a warning.
- **`Renderer.sharedMaterial` (singular) and `GetSharedMaterials(List<Material>)`.** They return the
  existing material, or fill your list, without copying. The plural `sharedMaterials` *is* reported:
  it does not instantiate materials the way `materials` does, but its getter still returns a new copy
  of the array on every read.
- **`GameObject.Find`, `FindWithTag` and `GetComponent<T>()`.** These return an existing object. They
  cost CPU time (a scene search, a component lookup) but create no garbage, which is outside what this
  rule measures. Since 1.6.1 [OPL009](OPL009.md) reports them.
- **`Resources.Load`, `Resources.LoadAsync` and Addressables loads.** They return a single object or a
  handle, not an array, and are reported by [OPL008](OPL008.md) (since 1.6.0) as a caching problem.
  `Resources.LoadAll` returns an array and stays with this rule.
- **Reads in methods called from the hot path, past `max_call_depth`.** Since 1.9.2, helpers are
  followed as for OPL001; see the [call graph](../configuration.md#helpers-called-from-a-hot-method-max_call_depth).
- **Burst-compiled code** (since 1.5.6). A method Burst compiles cannot call these APIs; see
  [Burst-compiled code](OPL001.md#burst-compiled-code).

## How to fix

| Allocating call | Non-allocating replacement |
| --- | --- |
| `GetComponents<T>()`, `GetComponentsInChildren<T>()`, `GetComponentsInParent<T>()` | The overload taking a `List<T>` held in a field, or cache the array once in `Awake` if the hierarchy does not change. |
| `Physics.RaycastAll`, `SphereCastAll`, `CapsuleCastAll`, `BoxCastAll` | `Physics.RaycastNonAlloc` and the other `*NonAlloc` variants, with a `RaycastHit[]` field. |
| `Physics.OverlapSphere`, `OverlapBox`, `OverlapCapsule` | `Physics.OverlapSphereNonAlloc` and siblings. |
| `Physics2D.*All` | The overloads taking a `ContactFilter2D` and a `List<T>` or array. |
| `Input.touches` | `Input.touchCount` with `Input.GetTouch(i)`. |
| `Camera.allCameras` | `Camera.allCamerasCount` with `Camera.GetAllCameras(Camera[])`. |
| `Mesh.vertices`, `normals`, `uv`, `triangles` | `Mesh.GetVertices(List<Vector3>)`, `GetNormals`, `GetUVs`, `GetTriangles` with reused lists. |
| `Renderer.materials` | `GetMaterials(List<Material>)` with a reused list, or `GetSharedMaterials(List<Material>)` if you do not need per-renderer copies. Reading `materials` also instantiates materials; see [below](#renderermaterials-and-material-instances). |
| `Renderer.sharedMaterials` | `GetSharedMaterials(List<Material>)` with a reused list, or `sharedMaterial` when the renderer has one material. `sharedMaterials` copies the array on every read. |
| `Animator.parameters`, `Animator.GetParameter(i)` | Read `parameters` once in `Awake` (the controller's parameters do not change at runtime), and drive the animator with IDs from `Animator.StringToHash`. |
| `Animator.GetLayerName(i)` | Cache the names in `Awake`, or use `GetLayerIndex(name)` once and keep the index. |
| `Application.dataPath`, `persistentDataPath`, `streamingAssetsPath`, `temporaryCachePath` | Read once into a `static readonly` field or a field set in `Awake`. |
| `Scene.name`, `Scene.path` | Compare `Scene.buildIndex` or `Scene.handle`, or cache the name when the scene loads (`SceneManager.sceneLoaded`). |
| `Scene.GetRootGameObjects()` | `GetRootGameObjects(List<GameObject>)` with a reused list. |
| `NavMeshAgent.path` | `agent.CalculatePath(target, reusedPath)`, or keep a `NavMeshPath` field. |
| `NavMeshPath.corners` | `NavMeshPath.GetCornersNonAlloc(Vector3[])` with a buffer field. |
| `JsonUtility.FromJson<T>(json)` | `JsonUtility.FromJsonOverwrite(json, existing)` into an object you keep. |
| `JsonUtility.ToJson(obj)` | Serialize on the event that changes the data, not every frame. |
| `Object.FindObjectsOfType<T>()` | Register instances in a static list from `OnEnable` and `OnDisable`. |
| `tag == "Player"` | `CompareTag("Player")`. |
| `name` | Cache it in a field in `Awake` if you need it every frame. |

### `Renderer.materials` and material instances

`Renderer.materials` (and `Renderer.material`, its single-material form) returns the renderer's own
copies of its materials. The first time either is read on a renderer that still uses the shared
materials from its asset, Unity *instantiates* them: it clones each shared `Material` into a new
`Material` object owned by that renderer, and assigns the clones to the renderer in place of the
originals. From then on the renderer no longer shares those materials with any other renderer, so:

- each clone is a new engine object, and editing it changes only this renderer;
- renderers that used to share a material can no longer be batched together, and draw calls can go up;
- the clones are not destroyed with the renderer. Unity frees them on a scene load or
  `Resources.UnloadUnusedAssets()`; until then, call `Destroy()` on them yourself when the renderer
  goes away, or they leak.

Later reads return the same clones, but still copy them into a new `Material[]`, which is the
allocation OPL003 reports. `GetMaterials(List<Material>)` fills a list you keep, but it instantiates
the materials just as `materials` does. To change a property on one renderer without cloning its
material, use a `MaterialPropertyBlock` with `Renderer.SetPropertyBlock`. Read `sharedMaterials` or
`GetSharedMaterials(List<Material>)` when you only need to inspect the materials, but remember that
editing a shared material changes it for every renderer that uses it, and in the Editor changes the
asset on disk. `Renderer.material`, which returns a single `Material` rather than an array, is not
reported.

## Code fixes

Three of the rewrites in the table above are offered as code fixes. Each is offered only for the shapes
listed here; any other use is still reported, with no fix. All three support **Fix All** in a document,
project or solution. As for [OPL002](OPL002.md#fix-all), Fix All applies the fixes one at a time,
because the buffer fix adds a field under a free name: two `GetComponentsInChildren<Collider>()` calls
in different methods get `_collidersBuffer` and `_collidersBuffer2`.

### Use CompareTag()

```csharp
// Before
if (other.tag == "Player") { }
var hostile = tag != PlayerTag;

// After
if (other.CompareTag("Player")) { }
var hostile = !CompareTag(PlayerTag);
```

Offered when:

- the `tag` read is one side of `==` or `!=`, and the other side is a `string` expression that is not
  `null`;
- the declaring type (`Component` or `GameObject`) has an instance `CompareTag(string)`;
- the tag is read as `x.tag` or plain `tag`, not through `?.`;
- when the string is on the left, it or the object whose tag is read has no side effects, because
  `x.CompareTag(s)` evaluates `x` before `s`.

`CompareTag` logs an error when the tag is not defined in the Tag Manager, where `==` returned `false`.
That usually points at a typo worth fixing.

### Fill a reused List&lt;T&gt; with the non-allocating overload

```csharp
// Before
var colliders = GetComponentsInChildren<Collider>();
for (int i = 0; i < colliders.Length; i++) { }

foreach (var renderer in GetComponentsInParent<Renderer>()) { }

// After
private readonly List<Collider> _collidersBuffer = new List<Collider>();
private readonly List<Renderer> _rendererBuffer = new List<Renderer>();

GetComponentsInChildren<Collider>(_collidersBuffer);
var colliders = _collidersBuffer;
for (int i = 0; i < colliders.Count; i++) { }

GetComponentsInParent<Renderer>(false, _rendererBuffer);
foreach (var renderer in _rendererBuffer) { }
```

Unity clears the list before filling it. `using System.Collections.Generic;` is added when missing.
Offered when:

- the call is an instance method of a `UnityEngine` type returning `T[]` for its one type argument,
  written with that type argument (`GetComponents<Collider>()`), and `T` is a reference type;
- the type has an overload with the same parameters plus a trailing `List<T>`, returning `void`. With
  no arguments, a `(bool, List<T>)` overload also qualifies and is called with `false`, the default
  the array overload uses; that is how `GetComponentsInParent<T>()` is rewritten;
- the call is the whole initializer of a local declared alone in a block, or the source of a `foreach`
  in a block;
- the method sits directly in a class and is not generic;
- every use of the local is an element access (`colliders[i]`), a `foreach` source, or `.Length`, which
  becomes `.Count`. The declaration becomes `var`, since the local now holds a `List<T>`.

The list is the same on every run, so code that keeps it past the frame has to copy it.

### Use Input.touchCount and Input.GetTouch()

```csharp
// Before
foreach (var touch in Input.touches)
{
    Move(touch.position);
}
if (Input.touches.Length > 1) { }
var first = Input.touches[0];

// After
for (int i = 0; i < Input.touchCount; i++)
{
    var touch = Input.GetTouch(i);
    Move(touch.position);
}
if (Input.touchCount > 1) { }
var first = Input.GetTouch(0);
```

Offered when `Input` has a static `touchCount` and a static `GetTouch(int)`, and `Input.touches` is:

- the source of a `foreach` whose variable is typed `var` or `Touch`. The loop index is `i`, or `i2`,
  `i3` and so on when the method already uses the name. A body without braces gets them;
- followed by `.Length`;
- indexed with one `int` argument, and the element is only read. `Input.touches[0].position.x = 1`
  compiles against the array but not against `GetTouch(0)`, so it gets no fix.

Storing the array (`var touches = Input.touches;`) gets no fix.

## When to suppress

Allocations behind a `Time.frameCount == 0` guard, inside `#if UNITY_EDITOR`, behind a static `bool`
latch the guarded branch sets, or assigned straight into a field are suppressed automatically —
`_cameras = Camera.allCameras;` is not reported, `var cameras = Camera.allCameras;` is. See
[Automatic suppressions](../suppressions.md).

Suppress on a path that runs once and latches, or in editor-only code:

```csharp
#pragma warning disable OPL003 // Allocating Unity API in hot path
        var renderers = GetComponentsInChildren<Renderer>();
#pragma warning restore OPL003
```

Or with an attribute on the containing member:

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage(
    "Performance", "OPL003:Allocating Unity API in hot path",
    Justification = "Editor-only gizmo drawing; not on the player hot path.")]
void OnDrawGizmos()
{
    ...
}
```

Change the severity project-wide from `.editorconfig`:

```ini
[*.cs]
# none | silent | suggestion | warning | error
dotnet_diagnostic.OPL003.severity = none
```
