# OPL001: Object allocation in hot path

| | |
|---|---|
| **Rule ID** | OPL001 |
| **Category** | Performance |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes (two) |

## Cause

An object is allocated inside a Unity message that the engine calls every frame (or every physics
step, or every GUI event). The rule reports two kinds of allocation:

- a `new` expression whose result is a reference type — including `new()`, array creation
  (`new int[8]`, `new[] { 1, 2 }`), and object/collection initializers;
- a `new` expression of a struct that is boxed on the spot — assigned to an `object` or interface
  variable, cast to one, passed as one, or returned as one (`object o = new MyStruct();`). The message
  names the target type: `'new MyStruct boxed to object' allocates inside ...`;
- a call to `UnityEngine.Object.Instantiate`.

The allocation must sit directly in the body of the message. An allocation inside a lambda or a local
function is only reported when that lambda or local function is invoked in place by the same body.
Allocations in helper methods called from the message are **not** reported — the analyzer does no
call-graph analysis.

The enclosing method must be an instance, non-generic method declared on a type deriving from
`UnityEngine.MonoBehaviour`, with the exact signature Unity requires for that message. The 18 covered
messages are:

`Update`, `FixedUpdate`, `LateUpdate`, `OnGUI`, `OnTriggerStay(Collider)`,
`OnTriggerStay2D(Collider2D)`, `OnCollisionStay(Collision)`, `OnCollisionStay2D(Collision2D)`,
`OnMouseOver`, `OnMouseDrag`, `OnAnimatorMove`, `OnAnimatorIK(int)`, `OnRenderObject`,
`OnWillRenderObject`, `OnPreRender`, `OnPostRender`, `OnDrawGizmos`, `OnDrawGizmosSelected`.

A method that shares a name but not the signature (`void Update(float dt)`, `static void Update()`)
is not a Unity message and is not flagged. If the compilation does not reference
`UnityEngine.MonoBehaviour` at all, the rule does not run.

The list can be extended with your own hot methods, and types can be excluded, from `.editorconfig` —
see [Configuration](#configuration). The same list and the same options apply to [OPL002](OPL002.md)
and [OPL003](OPL003.md).

### Burst-compiled code

Since 1.5.6, nothing is reported inside a method that Burst compiles: a method marked
`[BurstCompile]`, or declared in a type marked `[BurstCompile]`, when the method is `static` or belongs
to a struct. That covers a job struct's `Execute`, an `ISystem`'s `OnUpdate` and a static method in a
Burst class. Burst rejects managed allocations when it compiles, so the rule has nothing to add, and a
job's `Execute` listed in `additional_hot_methods` stays quiet. Local functions and lambdas inside
such a method are covered too.

`[BurstCompile]` does not silence everything it is written on. An instance method of a class, such as
a MonoBehaviour's `Update`, is never Burst-compiled, so the attribute on it or on its class changes
nothing and the method is still reported. A `[BurstDiscard]` method runs as managed code and is
reported too. The same rules apply to OPL002 and OPL003. A job struct that *holds* a managed field is
reported by [OPL006](OPL006.md).

## Why it matters

Unity's scripting runtime uses a non-generational garbage collector. Every object allocated in a
per-frame method stays alive until the next collection, so a single allocation in `Update` becomes
one allocation per frame per component instance — at 60 FPS with 100 enemies, 6,000 allocations a
second. The collector eventually runs, and on the incremental GC it spreads the cost across frames;
on the non-incremental one it stops the world. Either way the result is the frame hitch players see.

Pooling moves the allocation to load time: the objects are created once and handed out and returned,
so the steady-state per-frame allocation is zero and the collector has nothing to do.

## Example

Violation:

```csharp
using System.Collections.Generic;
using UnityEngine;

public class Enemy : MonoBehaviour
{
    void Update()
    {
        var hits = new List<Collider>();   // OPL001
        Scan(hits);
    }
}
```

Fix:

```csharp
using System.Collections.Generic;
using UnityEngine;

public class Enemy : MonoBehaviour
{
    private readonly List<Collider> _hits = new List<Collider>();

    void Update()
    {
        _hits.Clear();
        Scan(_hits);
    }
}
```

A reused field is the simplest fix when the object does not outlive the frame. When it does, or when
the count varies, take it from a pool and return it when you are done.

## Code fixes

Up to four quick actions are offered on a diagnostic:

1. **Replace with object pool Get()** — rewrites `new Enemy(hp)` to `EnemyPool.Get(hp)`, forwarding
   the constructor arguments unchanged. Offered when a pool matching the contract below already
   exists.
2. **Generate EnemyPool and use it here** — writes the pool, then rewrites the allocation to use
   it. Offered instead of the first fix when nothing answers to the pool's name. See
   [Generating the pool from the fix](#generating-the-pool-from-the-fix).
3. **Rent the array from ArrayPool&lt;T&gt;.Shared** — for an array allocation only, and only where
   the buffer provably stays inside its block. See [Arrays](#arrays).
4. **Add pooling TODO comment** — inserts a `// TODO:` reminder above the allocation. On an array
   creation the comment instead points at `ArrayPool<T>.Shared` and its two gotchas (see
   [Arrays](#arrays) below). On a boxed struct it suggests keeping the value typed as the struct, or
   boxing it once and reusing the box.

The first fix assumes a specific, narrow contract: a type named exactly `{TypeName}Pool`, visible at
the call site, with a static `Get` overload matching the constructor signature. Generic types map to
generic pools, so `new List<int>()` becomes `ListPool<int>.Get()`. **The fix itself writes nothing**
— if the pool type or the matching `Get` overload does not exist, the second fix takes over and
writes one. The full contract, with a copy-pasteable minimal pool, is in
[The pool contract](../../README.md#the-pool-contract).

The pool does not have to come from either fix: marking the allocated class `[ObjectPool]` generates
one that satisfies the contract, so the first fix becomes available for it. See
[Generating pools with `[ObjectPool]`](../source-generator.md).

Neither pool fix is offered for array creations (see [Arrays](#arrays)), for boxed structs (a pooled
struct is boxed again at the same conversion, so nothing is saved), or for allocations carrying an
object or collection initializer (`new Enemy { Hp = 5 }`), because an initializer cannot be attached
to a method call and dropping it would silently lose code. Use the TODO-comment fix there and
rewrite by hand.

### Generating the pool from the fix

When no type answers to `{TypeName}Pool` at the allocation site, the fix writes one: a
`Stack<T>`-backed static class beside the type the allocation is in, with `Get` forwarding to the
constructor that was used, plus `Return`, `Clear` and `CountInactive`, and the allocation rewritten
to call it.

```csharp
void Update()
{
    var enemy = EnemyPool.Get(5);
}

/// <summary>
/// Object pool for <c>Enemy</c>. Not thread-safe, which is enough for
/// Unity's main-thread messages. Every instance taken out has to be handed back once.
/// </summary>
public static class EnemyPool
{
    private static readonly System.Collections.Generic.Stack<Enemy> s_free = new System.Collections.Generic.Stack<Enemy>();

    public static int CountInactive
    {
        get { return s_free.Count; }
    }

    public static Enemy Get(int hp)
    {
        if (s_free.Count == 0) return new Enemy(hp);

        Enemy instance = s_free.Pop();
        // TODO: put instance back into the state new Enemy(int hp) would leave it in.
        return instance;
    }

    public static void Return(Enemy instance)
    {
        if (instance == null) throw new System.ArgumentNullException("instance");

        // TODO: release whatever instance holds on to before it waits in the pool.
        s_free.Push(instance);
    }

    public static void Clear()
    {
        s_free.Clear();
    }
}
```

The pool is ordinary source in your own file: edit it, move it, rename the file around it. The two
`TODO` comments mark the decisions the fix cannot make — resetting a recycled instance, and
releasing what it holds — and **where `Return` is called stays yours to write**. A pool nothing is
returned to is a leak with extra steps.

A generic type generates a generic pool with the same constraints, so `new List<int>()` produces
`ListPool<T>` and calls `ListPool<int>.Get()`.

The fix is not offered when:

- something already answers to the name `{TypeName}Pool` at that spot, whatever it is;
- the type is abstract, static, a `UnityEngine.Object` (those need `Instantiate`), or nested in a
  generic type;
- the type or its constructor cannot be reached from the file's namespace level;
- an optional argument is omitted or a `params` list is expanded at the call site, because arguments
  are forwarded to `Get` unchanged. Write the arguments out and the fix appears.

For a type you own, marking it `[ObjectPool]` is usually the better answer: the generated pool stays
in step with the constructors, costs nothing in your source tree, and declares a reset hook per
overload. See [Generating pools with `[ObjectPool]`](../source-generator.md). This fix is for the
types you do not own, and for a pool you want to edit by hand.

### Arrays

`new int[4]` and `new[] { 1, 2 }` are reported. The object-pool fixes do not apply to them, because
`ArrayPool<T>.Shared` is not a drop-in replacement:

- `ArrayPool<T>.Shared.Rent(4)` returns an array whose `Length` is **at least** 4, not exactly 4.
  Any code that reads `buffer.Length`, iterates the array without a separate count, or passes it to
  an API that consumes the whole array changes behaviour silently.
- A rented array has to be handed back with `ArrayPool<T>.Shared.Return(buffer)` on every exit path,
  including exceptions. Where that call belongs depends on the buffer's lifetime, which a rewrite
  cannot infer in general.

**Rent the array from ArrayPool&lt;T&gt;.Shared** covers the narrow case where both objections can be
answered mechanically: a local buffer, declared with its length, that the rest of its block only
indexes and reads `Length` from.

```csharp
// before
void Update()
{
    var buffer = new int[4];
    for (int i = 0; i < buffer.Length; i++) buffer[i] = i;
}

// after
void Update()
{
    int bufferLength = 4;
    var buffer = System.Buffers.ArrayPool<int>.Shared.Rent(bufferLength);
    try
    {
        for (int i = 0; i < bufferLength; i++) buffer[i] = i;
    }
    finally
    {
        System.Buffers.ArrayPool<int>.Shared.Return(buffer);
    }
}
```

The length that was asked for moves into its own local, and every `buffer.Length` in the block is
redirected to it, so the extra capacity a rented array may carry is never read as the logical length.
That local is added only when something reads `Length`, and the size expression is evaluated once.
For an array of a reference type the buffer is returned with `clearArray: true`, or the pool would
keep the elements alive for as long as it holds the buffer.

The fix is not offered when the buffer could outlive the block: passed as an argument, assigned to
anything, returned, enumerated with `foreach`, or captured by a lambda or a local function. It is
also not offered for an array with an initializer, a multi-dimensional array, a `const` or `using`
declaration, a declaration that is not directly inside a block, or where the statements it would wrap
contain a `yield`. `System.Buffers.ArrayPool<T>` has to exist in the compilation, which it does from
Unity's .NET Standard 2.1 profile onwards.

Where the fix does not apply, the decision stays with you. The usual fixes, in order of preference:

1. Hoist the array to a field and reuse it across frames, when the size is fixed and the contents do
   not need to survive the frame.
2. Use a Unity API that fills a caller-supplied buffer — `Physics.RaycastNonAlloc`,
   `GetComponentsInChildren(List<T>)` — instead of one that returns a fresh array.
3. Rent from `ArrayPool<T>.Shared` by hand, tracking the logical length yourself and returning the
   buffer in a `finally`.

## Configuration

`.editorconfig` options adjust which methods the rule treats as hot paths. They are shared by OPL001,
OPL002 and OPL003, and the full reference, with setup steps, is in
[Configuring ObjectPoolLinter](../configuration.md).

```ini
[*.cs]
# Also treat these methods as hot paths. A parameter list picks one overload.
object_pool_linter.additional_hot_methods = Tick(float), Simulate, OnPreCull, EnemyBrain.Think

# Never report inside methods declared on these types.
object_pool_linter.excluded_types = LoadingScreen, Game.Editor.GizmoDrawer
object_pool_linter.excluded_types_regex = ^Game\.Debug\.
```

### `object_pool_linter.additional_hot_methods`

Methods reported in addition to the 18 built-in Unity messages. Use it for custom update loops
(`Tick()` driven by a manager, Zenject's `ITickable.Tick`, a fixed-step `Simulate`) and for per-frame
Unity messages the built-in list leaves out (`OnPreCull`).

- A bare name (`Tick`) matches a method with that name on **any** type, not only MonoBehaviours, with
  **any** parameter list, static or instance. Custom loops usually live on plain classes and take a
  delta time, so the signature checks applied to Unity messages do not apply here.
- A type-qualified name (`EnemyBrain.Think`, `Game.AI.EnemyBrain.Think`) matches only methods declared
  on that type. The type part follows the naming rules below.
- A parameter list (`Tick(float)`, `EnemyBrain.Think()`, `Step(ref Vector3, float)`) matches only the
  overload with exactly those parameter types. Types can be written as C# keywords, simple names or
  namespace-qualified names; `ref`, `out` and `in` must match. See
  [Hot methods](../configuration.md#hot-methods-additional_hot_methods).

The message names the method as usual:
`'new List<float>' allocates inside the frequently-called method 'Tick'.`

### `object_pool_linter.excluded_types` and `object_pool_linter.excluded_types_regex`

Types whose methods are never reported — built-in messages and additional hot methods alike. Use them
for a MonoBehaviour whose `Update` genuinely runs rarely (a loading screen, a debug overlay) instead of
scattering pragmas through it.

- `excluded_types` is a comma-separated list of type names, following the naming rules below.
- `excluded_types_regex` is one .NET regular expression, matched case-sensitively and unanchored
  against the namespace-qualified name (`Game.Debug.Overlay`), so `^Game\.Debug\.` excludes a whole
  namespace. See [Excluded types](../configuration.md#excluded-types-excluded_types-and-excluded_types_regex).
- The exclusion applies to methods **declared** on the matched type. Types deriving from it are still
  analyzed; list them separately.
- An exclusion wins over `additional_hot_methods`.

### Type names

A type is named by its simple name (`LoadingScreen`) or its namespace-qualified name
(`Game.UI.LoadingScreen`). Nested types use dots (`Game.Outer.Inner`), generic types are named without
their type parameters (`Pool`, not `Pool<T>`), and a leading `global::` is ignored. A simple name
matches every type with that name in any namespace; qualify it to pick one.

### Where the options apply

Options are read per file, so an `.editorconfig` in a subfolder can add or exclude methods for just
that folder, and a global `.globalconfig` works too. A subfolder's value replaces the parent's rather
than adding to it ([How files combine](../configuration.md#how-files-combine)). The options are
honoured by `dotnet build`, Visual Studio, Rider and VS Code. Unity's own editor compile has not been
verified to pass them to analyzers; if the IDE reports a diagnostic that the Unity Console does not
(or the other way round), that is the likely cause.

A misspelled option name or an unusable value is reported by [OPL004](OPL004.md) instead of being
silently ignored.

The options only change *where* the rule looks. If the compilation does not reference
`UnityEngine.MonoBehaviour`, the rule still does not run, even for additional hot methods.

## What the rule does not cover

OPL001 matches `new` expressions and `Instantiate` only. Allocations without a `new` in the source
have their own rules:

- [OPL002](OPL002.md) reports string concatenation and interpolation, capturing lambdas, method-group
  delegates, implicit `params` arrays, LINQ (including LINQ-style extension methods), boxing of
  anything other than a freshly created struct (`object o = count;`, a struct receiver calling a
  non-overridden `object` method), the state machines created by calling iterator and `async`
  methods, and a `foreach` that gets its enumerator through an interface.
- [OPL003](OPL003.md) reports Unity engine APIs that return a new array (`GetComponentsInChildren<T>()`,
  `Physics.RaycastAll`, `Camera.allCameras`, `Input.touches`) and `name` / `tag`.
- [OPL006](OPL006.md) reports a managed field in a Unity job struct, wherever the struct is declared.

No rule does call-graph analysis. The full list of boundaries is in
[Known limitations](../../README.md#known-limitations).

## When to suppress

Four shapes are suppressed for you: a `Time.frameCount == 0` guard, `#if UNITY_EDITOR`, a static
`bool` latch the guarded branch sets, and an allocation assigned straight into a field. See
[Automatic suppressions](../suppressions.md), which also covers switching any of them off.

Suppress the rest by hand when the allocation is genuinely not per-frame — a `Debug.DrawLine`
helper in `OnDrawGizmos`, a branch guarded in a way the suppressor cannot see through — or when
the object must escape the frame and pooling would be more error-prone than the garbage it
avoids.

Suppress a single site with a pragma:

```csharp
#pragma warning disable OPL001 // Object allocation in hot path
        var oneShot = new StringBuilder();
#pragma warning restore OPL001
```

Or with an attribute on the containing member:

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage(
    "Performance", "OPL001:Object allocation in hot path",
    Justification = "Editor-only gizmo drawing; not on the player hot path.")]
void OnDrawGizmos()
{
    ...
}
```

Change the severity project-wide from `.editorconfig`:

```ini
[*.cs]
# none | silent | suggestion | warning | error
dotnet_diagnostic.OPL001.severity = suggestion
```

`dotnet_diagnostic.OPL001.severity = none` turns the rule off entirely. In Unity, put the
`.editorconfig` at the project root next to `Assets/`, or in any folder above the scripts it should
apply to.
