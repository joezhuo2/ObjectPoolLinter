# OPL004: Invalid ObjectPoolLinter option

| | |
|---|---|
| **Rule ID** | OPL004 |
| **Category** | Configuration |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | No |

## Cause

An `object_pool_linter.*` entry in `.editorconfig` or `.globalconfig` has no effect, because:

- its name is not one the linter reads (`object_pool_linter.exlude_types`), including an unknown
  per-kind severity such as `object_pool_linter.closure_severity`, for which the message lists the
  eight kinds;
- its prefix is misspelled (`object_pool_lintr.excluded_types`, `objectpoollinter.excluded_types`,
  `object-pool-linter.excluded_types`), so the linter never reads it (since 1.9.7);
- its value cannot be used: an `additional_hot_methods` entry that is not a method name, a
  `*_severity` value that is not a severity, an `excluded_types_regex` that is not a valid regular
  expression, a `suppressions` entry that is not a suppression name, or a `telemetry` value that is
  not `true` or `false`; or
- it is a per-kind OPL002 severity that a rule-wide one overrides (since 1.9.7).
  `dotnet_diagnostic.OPL002.severity` (from `.editorconfig`, `.globalconfig`, a rule set or `<NoWarn>`)
  or `dotnet_analyzer_diagnostic.category-Performance.severity` is applied by the compiler to every
  OPL002 diagnostic after the analyzer has picked the kind's severity, so
  `object_pool_linter.string_severity = suggestion` next to `dotnet_diagnostic.OPL002.severity = warning`
  does nothing. A kind set to `none` or `default`, or to the same severity as the rule-wide line, is
  not reported: it still does what it says.

Without this rule a typo is silently ignored, and the rules go on reporting (or not reporting)
methods as if the line were not there.

## Examples

```ini
[*.cs]
object_pool_linter.exlude_types = LoadingScreen
object_pool_linter.linq_severity = loud
object_pool_linter.additional_hot_methods = Tick(float
object_pool_linter.excluded_types_regex = Overlay(
object_pool_linter.suppressions = cached_fields
object_pool_lintr.max_call_depth = 1
object_pool_linter.closure_severity = warning

dotnet_diagnostic.OPL002.severity = warning
object_pool_linter.string_severity = suggestion
```

```
warning OPL004: ObjectPoolLinter option ignored: 'object_pool_linter.exlude_types' is not a recognized option. Did you mean 'object_pool_linter.excluded_types'?
warning OPL004: ObjectPoolLinter option ignored: 'loud' in 'object_pool_linter.linq_severity' is not a severity. Use none, silent, suggestion, warning, error or default.
warning OPL004: ObjectPoolLinter option ignored: 'Tick(float' in 'object_pool_linter.additional_hot_methods' has a parameter list that does not end with ')'.
warning OPL004: ObjectPoolLinter option ignored: 'Overlay(' in 'object_pool_linter.excluded_types_regex' is not a valid regular expression.
warning OPL004: ObjectPoolLinter option ignored: 'cached_fields' in 'object_pool_linter.suppressions' is not a suppression. Use all, none, first_frame, editor_only, static_latch or cached_field.
warning OPL004: ObjectPoolLinter option ignored: 'object_pool_lintr.max_call_depth' is not a recognized option. Did you mean 'object_pool_linter.max_call_depth'?
warning OPL004: ObjectPoolLinter option ignored: 'object_pool_linter.closure_severity' is not a recognized option. The per-kind OPL002 severities are string_severity, delegate_severity, params_severity, linq_severity, boxing_severity, iterator_severity, async_severity and enumerator_severity.
warning OPL004: ObjectPoolLinter option ignored: 'suggestion' in 'object_pool_linter.string_severity' has no effect, because 'dotnet_diagnostic.OPL002.severity' is set and the compiler applies it to every OPL002 diagnostic. Remove that line to use per-kind severities.
```

An unusable `suppressions` value leaves every suppression pattern on, rather than narrowing the set
to whatever else the line named.

## How to fix

Correct the name or value the message quotes. The recognized options and the values they take are
listed in [Configuring ObjectPoolLinter](../configuration.md#option-reference).

A bad entry in `additional_hot_methods` drops only that entry: with `Brain..Think, Simulate`,
`Simulate` still applies. An unclosed parenthesis is the exception, since the commas after it are read
as part of the parameter list: `Tick(float, Simulate` is one bad entry, and `Simulate` is lost with it.

## Where it is reported

- Once per project and per distinct problem, however many files the `.editorconfig` covers.
- With no source location: the problem is in a config file, not in a `.cs` file. It appears in build
  output (`CSC : warning OPL004: ...`) and in the IDE's error list when full-solution analysis is on,
  not as a squiggle.
- In every MSBuild build that runs analyzers. To fail the build on a bad option, set
  `dotnet_diagnostic.OPL004.severity = error` or add `OPL004` to `WarningsAsErrors`; see
  [In an MSBuild build](../configuration.md#in-an-msbuild-build).
- Options outside the `object_pool_linter.` prefix, such as `dotnet_diagnostic.*` and style settings,
  are not checked themselves. A first segment close to `object_pool_linter` (two edits or fewer, or the
  same letters without `_` and `-`) is treated as a misspelled prefix. `dotnet_diagnostic.OPL002.severity`
  and the Performance category line are read only to find a per-kind severity they override. The
  compiler does not pass `dotnet_diagnostic.*` lines to analyzers as options, so a line for an ID no
  rule has, such as `dotnet_diagnostic.OPL042.severity`, is not reported.

Misspelled option *names* are found only on compilers that can list the options they hold. The
analyzer builds against Roslyn 3.8, which cannot, and asks for the list at run time; the .NET 10 SDK
and other recent compilers provide it. Where it is not available, invalid *values* are still reported.

## When to suppress

Fix the option instead. If a shared `.editorconfig` deliberately carries options for a newer version
of the linter than one project uses, turn the rule off for that project:

```ini
[*.cs]
dotnet_diagnostic.OPL004.severity = none
```
