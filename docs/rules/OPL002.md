# OPL002: Hidden allocation in hot path

| | |
|---|---|
| **Rule ID** | OPL002 |
| **Category** | Performance |
| **Default severity** | Info |
| **Enabled by default** | Yes |
| **Code fix** | Yes, for capturing lambdas, method-group delegates, string interpolation and simple LINQ chains ([Code fixes](#code-fixes)) |

## Cause

Code inside a hot path allocates without a `new` expression: the compiler or the base class library
allocates on its behalf. The rule reports these constructs:

| Construct | Example | Message names it as |
| --- | --- | --- |
| String concatenation | `label + ": " + hp`, `log += "tick"` | `string concatenation` |
| String interpolation | `$"hp: {hp}"` | `string interpolation` |
| An explicit `string.Concat` call, any overload | `string.Concat(a, b, c)`, `string.Concat(parts)` | `string.Concat()` |
| A `string.Format` call, any overload | `string.Format("hp: {0}", hp)` | `string.Format()` |
| `StringBuilder.ToString()` | `builder.ToString()`, `builder.ToString(0, 4)` | `StringBuilder.ToString()` |
| A lambda that captures state | `() => count + 1`, or `() => wave + 1` reading a field (captures `this`) | `lambda capturing count` |
| A method group converted to a delegate | `Action a = Spawn;`, `button.onClick += OnClick;` | `delegate for Spawn()` |
| An implicit `params` array | `Show("{0} {1}", a, b)` against `Show(string, params string[])` | `params string[] for Show()` |
| LINQ | `hp.Where(h => h > 0).ToList()`, `from h in hp select h` | `LINQ Where().ToList()`, `LINQ query` |
| A LINQ-style extension method from any other class (since 1.5.5) | `hp.WhereAlive()`, `hp.Where(h => h > 0).TakeEvery(2).ToList()` | `LINQ WhereAlive()`, `LINQ Where().TakeEvery().ToList()` |
| Boxing an existing value | `object o = count;`, `IComparable c = count;` | `boxing int to object` |
| A struct calling an `object` method it does not override | `cell.GetHashCode()` | `boxing Cell for GetHashCode()` |
| A call to an iterator method (since 1.5.5) | `StartCoroutine(Spawn())`, `foreach (var e in Nearby())` | `iterator state machine for Spawn()` |
| A call to an async method (since 1.5.5) | `_ = SaveAsync();`, `await LoadAsync();` | `async state machine for SaveAsync()` |
| A hot method that is itself an iterator or async method (since 1.5.5) | `async void Update()`, a `Tick` listed in `additional_hot_methods` that uses `yield return` | `async state machine for Update()` |

The full message reads:
`'string interpolation' allocates inside the frequently-called method 'Update'. Move it out of the method or cache the result.`

Which methods count as hot paths follows [OPL001](OPL001.md#cause): the 18 built-in Unity messages on
a `MonoBehaviour`, plus whatever `.editorconfig` adds or excludes (see
[Configuration](OPL001.md#configuration)). The code must sit directly in the method body, or in a
lambda or local function the body invokes in place.

### LINQ-style extension methods

`System.Linq.Enumerable` is not the only source of LINQ allocations. An extension method from any
class whose `this` parameter is `IEnumerable<T>` or `IEnumerable` (MoreLINQ, a project's own
`WhereAlive()` helper) is reported the same way: it enumerates through the interface, which boxes a
`List<T>` or array enumerator, and a lazy operator allocates its own iterator on top. Such calls join
an `Enumerable` chain, so `hp.Where(...).TakeEvery(2).ToList()` is still reported once, and a
LINQ-style extension that is also an iterator is reported as LINQ only. They share
`object_pool_linter.linq_severity`.

### Iterator and async state machines

The compiler turns a method with `yield return` or `yield break` into a state machine class, and every
call creates one. Calling an iterator in a hot path (a coroutine started every frame, a `foreach` over
an iterator method) is reported at the call, as `iterator state machine for Spawn()`.

An `async` method's state machine is reported the same way at each call, as
`async state machine for SaveAsync()`, when the method returns `void`, `Task`, `Task<T>`, `ValueTask`
or `ValueTask<T>`. Those builders move the state machine to the heap the first time the method awaits
something that has not finished, and a `Task<T>` result is itself an object. In a Debug build, which is
what the Unity Editor compiles by default, the state machine is a class and allocates on every call.

A hot method that is itself an iterator or async method, such as `async void Update()`, allocates its
state machine each time Unity (or the manager driving a custom update loop) calls it. It is reported
once, on the method name, rather than on each `yield` or `await`.

Methods in source are recognized from their syntax. Methods in a compiled assembly are recognized by
the `[IteratorStateMachine]`, `[AsyncIteratorStateMachine]` and `[AsyncStateMachine]` attributes the
compiler puts on them; reference assemblies usually strip those, so calls into a reference-only
assembly are not reported.

## Why it is Info by default

Formatting a debug string or running a short LINQ query in `Update` is common in code that is not
performance-critical, and a warning on every one would bury the OPL001 warnings that matter more. The
rule is on, but reports as a suggestion. Raise it once a project is ready to act on it:

```ini
[*.cs]
dotnet_diagnostic.OPL002.severity = warning
```

Unity's Console shows warnings and errors only, so in the Unity Editor OPL002 appears only after it is
raised to `warning`. IDEs show Info diagnostics as suggestions.

### Per-kind severity

Each kind of allocation can have its own severity, so LINQ and boxing can warn while string
formatting stays a suggestion:

```ini
[*.cs]
# none | silent | suggestion | warning | error | default
object_pool_linter.linq_severity = warning
object_pool_linter.boxing_severity = warning
object_pool_linter.delegate_severity = suggestion
object_pool_linter.string_severity = suggestion
object_pool_linter.params_severity = none
```

| Option | Covers |
| --- | --- |
| `object_pool_linter.string_severity` | string concatenation and interpolation, `string.Concat()`, `string.Format()`, `StringBuilder.ToString()` |
| `object_pool_linter.delegate_severity` | capturing lambdas and method-group delegates |
| `object_pool_linter.params_severity` | implicit `params` arrays |
| `object_pool_linter.linq_severity` | LINQ method chains and query expressions |
| `object_pool_linter.boxing_severity` | boxing conversions and struct calls to `object` methods |
| `object_pool_linter.iterator_severity` | calls to iterator methods, and hot methods that are iterators (since 1.5.5) |
| `object_pool_linter.async_severity` | calls to async methods, and hot methods that are async (since 1.5.5) |

`dotnet_diagnostic.OPL002.severity`, when set, is applied by the compiler afterwards and wins over the
per-kind options, so leave it out to use them. The exception is `none`: a kind set to `none` is never
reported. Each diagnostic also carries its kind in the `AllocationKind` property (`string`, `delegate`,
`params`, `linq`, `boxing`, `iterator`, `async`). Details: [Per-kind OPL002 severity](../configuration.md#per-kind-opl002-severity).

## What is not reported, and why

- **Constant strings.** `"a" + "b"` and `const` concatenations are folded at compile time.
- **Interpolated strings with no holes.** `$"text"` compiles to a literal.
- **A chain of `+` or of LINQ calls is reported once**, on the outermost expression, because it is one
  site to fix.
- **Lambdas that capture nothing.** The compiler caches them in a static field, so they allocate once.
- **Static method groups under C# 11 or later.** C# 11 caches those delegates too. Under C# 9, which
  Unity 2021.3 through Unity 6 compile with, they allocate and are reported.
- **`new Action(Spawn)` and `new object[] { a, b }`.** These are `new` expressions, reported by OPL001.
- **A struct boxed as it is created** (`object o = new Vector3();`) is OPL001's.
- **Boxing inside a concatenation or an interpolation hole** is part of the string allocation already
  reported, so it is not reported twice.
- **The `params` array and argument boxing of a `string.Concat` or `string.Format` call.**
  `string.Format("{0} {1} {2} {3}", hp, mp, xp, lvl)` builds an `object[]` and boxes four `int`s, but
  they are one call site to fix, so only `string.Format()` is reported.
- **`a + b` as `string.Concat`.** The compiler lowers `+` to `string.Concat`, but it is reported once,
  as `string concatenation`.
- **Other `StringBuilder` members.** `Append`, `Clear` and `AppendFormat` write into the builder's
  existing buffer, which grows only when it runs out of capacity.
- **An empty `params` expansion.** `Show("text")` passes `Array.Empty<string>()`.
- **`Enumerable.Empty<T>()`**, which returns a cached instance.
- **Extension methods that do not take the sequence as `IEnumerable<T>` or `IEnumerable`.** An
  extension on `List<T>`, `T[]` or `IReadOnlyList<T>` can index without an enumerator, and one on a
  generic `TSource` constrained to `IEnumerable<T>` enumerates the struct enumerator directly, so
  neither counts as LINQ-style.
- **Async methods with a pooling builder.** An async method returning a task-like type other than
  `Task`, `Task<T>`, `ValueTask` or `ValueTask<T>` (UniTask, Unity's `Awaitable`), or one marked
  `[AsyncMethodBuilder(...)]` (such as `PoolingAsyncValueTaskMethodBuilder`), brings a builder that
  reuses its state machines.
- **A `yield` inside a lambda or local function** makes that function the iterator, not the method
  around it.
- **Iterator property getters** (`IEnumerable<int> Items { get { yield return 1; } }`). Only method
  calls are checked for state machines.
- **An unconstrained generic `T` converted to `object`.** It boxes only when `T` is a value type at
  run time, which the analyzer cannot know.
- **Allocations in methods called from the hot path.** As with OPL001, there is no call-graph analysis.
  Calling an iterator or async method is the exception: the state machine is created at the call, so
  the call is reported. What the method allocates in its own body still is not.

## How to fix

| Construct | Fix |
| --- | --- |
| String concatenation, interpolation, `string.Concat` or `string.Format` | Build the string only when the value changes, not every frame: cache the last value and compare. A `StringBuilder` held in a field, cleared and reused, avoids intermediate strings. |
| `StringBuilder.ToString()` | Call it only when the text changed, and cache the result. APIs that accept a `StringBuilder` or a `char[]` directly (such as TextMesh Pro's `SetText(StringBuilder)`) skip the string altogether. |
| Capturing lambda | Create the delegate once (in `Awake` or a field initializer) and reuse it, or pass state through a parameter so the lambda captures nothing. |
| Method-group delegate | Cache it: a `private Action _spawn;` assigned once in `Awake`, then `button.onClick += _spawn;`. |
| `params` array | Call an overload with a fixed parameter list, or pass an array held in a field. |
| LINQ, including LINQ-style extensions | Replace with a `for` or `foreach` loop, filling a reused `List<T>`. For your own extension methods, add an overload that takes `List<T>` or `T[]` and indexes it. |
| Iterator call | Fill a reused `List<T>` instead of yielding. For a coroutine, start it once (in `OnEnable` or `Start`) and loop inside it with `while (true) { ...; yield return null; }`. |
| Async call | Start the work once rather than every frame. If the method never awaits anything that is still running, make it synchronous; otherwise return a pooled task type such as UniTask or `Awaitable`. |
| Iterator or async hot method | Keep `Update` synchronous and start the iterator or async work from `Start` or `OnEnable`. |
| Boxing | Keep the value typed as the struct. Use `EqualityComparer<T>.Default` for generic comparisons, and override `GetHashCode`, `Equals` and `ToString` on your own structs. |

## Code fixes

Four constructs have a rewrite. A fix is offered only for the shapes listed under it, because those are
the shapes it can rewrite without changing what the code does. Every other shape is still reported,
with no fix; use the table above. None of the fixes supports fix-all.

### Cache the lambda in a field assigned in Awake()

```csharp
// Before
void Update()
{
    var count = 3;
    Run(() => count + 1);
}

// After
private int count;
private Func<int> _next;

private void Awake()
{
    _next = () => count + 1;
}

void Update()
{
    count = 3;
    Run(_next);
}
```

The delegate is created once, in `Awake()`. Each local the lambda captures becomes a field of the same
name, and its declaration becomes an assignment, so the lambda and the rest of the method still share
the variable. The value now survives between frames instead of being a fresh variable on each call.
The field for the delegate is named after where the lambda goes: the variable it initializes, the
member it is assigned or added to, or the parameter it is passed as (`_next` above), with a number
appended when the name is taken.

Offered when all of these hold:

- the class derives from `MonoBehaviour`, and the method is a non-generic instance method other than
  `Awake`;
- `Awake()` either exists in the class with a block body, or exists nowhere in the class or its base
  classes (a new `Awake()` would hide an inherited one);
- the lambda is not nested inside another lambda or a local function;
- it captures no parameter and calls no local function of the method;
- every captured local is declared on its own (`var count = 3;`, not `int a = 1, b = 2;`) with an
  initializer, outside any loop, is not `const`, `ref` or `using`, and its name is not already a member
  of the class, a name used in `Awake()`, or a name that binds to anything but a local elsewhere in the
  class.

### Cache the delegate in a field assigned in Awake()

```csharp
// Before
void Update()
{
    Action callback = Spawn;
}

// After
private Action _spawn;

private void Awake()
{
    _spawn = Spawn;
}

void Update()
{
    Action callback = _spawn;
}
```

The field is named after the method. The same `MonoBehaviour` and `Awake()` conditions as the lambda fix
apply. The method group must be a method of the class itself (`Spawn`, `this.Spawn`, `base.Spawn`) or a
static method (`Helpers.Spawn`): `enemy.Die` binds to whatever `enemy` holds when the hot method runs,
so it gets no fix, and neither does a local function.

### Build the string with a reused StringBuilder

```csharp
// Before
void Update()
{
    var text = $"hp: {hp}";
}

// After (using System.Text; is added when missing)
private readonly StringBuilder _textBuilder = new StringBuilder();

void Update()
{
    _textBuilder.Clear().Append("hp: ").Append(hp);
    var text = _textBuilder.ToString();
}
```

The builder is a field (a `static` field in a `static` method), cleared and refilled on each run. Holes
of type `string`, `char`, `bool` or a numeric type, and reference types other than arrays, are appended
directly. Anything else (a struct, an enum, an array, `null`) is appended as `(object)value`, which
formats it the way interpolation does; that boxing is still reported. `ToString()` still allocates the
final string, and OPL002 reports it as `StringBuilder.ToString()`: the fix removes the intermediate
strings, not the result. To avoid the result too, build the string only when the value changes, or
hand the builder to an API that accepts one.

Offered when all of these hold:

- the interpolated string is converted to `string` (not to `FormattableString` or a handler type);
- no hole has an alignment or a format (`{hp,5}`, `{speed:F2}`);
- it sits in a local declaration, an expression statement or a `return` directly inside a block, outside
  any lambda or local function;
- it is always evaluated: not in a branch of `?:`, the right side of `&&`, `||` or `??`, a `?.` chain, a
  `switch` expression, or `??=`;
- everything the statement evaluates before it is a plain read (a name, member access, literal, cast,
  indexer or arithmetic on those), because the holes now run before the statement. Property getters
  count as plain reads.

### Replace LINQ with a loop filling a reused List&lt;T&gt;

```csharp
// Before
void Update()
{
    var alive = hp.Where(h => h > 0).Select(h => h * 2).ToList();
}

// After
private readonly List<int> _aliveBuffer = new List<int>();

void Update()
{
    _aliveBuffer.Clear();
    for (int i = 0; i < hp.Count; i++)
    {
        var h = hp[i];
        if (h > 0)
            _aliveBuffer.Add(h * 2);
    }
    var alive = _aliveBuffer;
}
```

`alive` now refers to the same list on every run, and the next run clears it. Code that stores the
result past the current frame, or compares it with an earlier result, has to copy it first. When the
source is anything but a local, a parameter or a field, it is read once into a local named `source`.
The loop variable takes the lambda's parameter name, and a new name gets a number appended when the
method already uses it. `using System.Collections.Generic;` is added when missing.

Offered when all of these hold:

- the chain is `Where(...).ToList()`, `Select(...).ToList()` or `Where(...).Select(...).ToList()`,
  written as extension calls;
- the source is a `List<T>` or a single-dimensional array;
- each lambda has one parameter of the element type and an expression body, and is not `async` (the
  `Where((h, i) => ...)` index overloads are not matched);
- the element type can be written in a field declaration (no anonymous types);
- the chain meets the same statement conditions as the `StringBuilder` fix.

## When to suppress

Allocations behind a `Time.frameCount == 0` guard, inside `#if UNITY_EDITOR`, behind a static `bool`
latch the guarded branch sets, or assigned straight into a field are suppressed automatically —
`_label = first + second;` is not reported, `var label = first + second;` is. See
[Automatic suppressions](../suppressions.md).

Suppress when the code runs rarely despite sitting in a hot method (a branch that latches after the
first frame), or on an editor-only path. The mechanisms are the same as for OPL001:

```csharp
#pragma warning disable OPL002 // Hidden allocation in hot path
        Debug.Log($"spawned wave {wave}");
#pragma warning restore OPL002
```

```ini
[*.cs]
# none | silent | suggestion | warning | error
dotnet_diagnostic.OPL002.severity = none
```
